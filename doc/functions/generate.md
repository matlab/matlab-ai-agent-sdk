# generate
<a id="generate"></a>

Generate output from large language models (LLMs)
## Syntax
<a id="syntax"></a>

`[text,message,info] = generate(client,prompt)`

`[text,message,info] = generate(client,messageHistory)`

`[text,message,info] = generate(___,Name=Value)`
## Description
<a id="description"></a>

`[text,message,info] = generate(client,prompt)`
generates output from an LLM client `client` given a single user prompt
`prompt`.

`[text,message,info] = generate(client,messageHistory)`
generates output using the message history `messageHistory`.

`[text,message,info] = generate(___,Name=Value)`
specifies additional options using one or more name-value arguments. For example, to set a
timeout of 30 s, set [`TimeOut`](#timeout) to `30`.
## Examples
<a id="examples"></a>
### Generate Text Using Large Language Model (LLM)
<a id="generate-text-using-large-language-model-llm"></a>

To generate text using the LLM API `api` and the model `model`, first create the LLM client by using the [`aisdk.LLMClient`](aisdk.LLMClient.md) function. Then, generate text by using the [`generate`](generate.md) function.

```
client = aisdk.LLMClient(api,model);
prompt = "This is an example prompt.";
generate(client,prompt)
```

```
ans =
  "This is an example response generated by an LLM."
```
### Manually Track Message History
<a id="manually-track-message-history"></a>

To track the message history during a conversation with an LLM, store
the messages as an `LLMMessage` array and pass that message array to the
[`generate`](generate.md) function.

When you create an AI agent by using the [`aisdk.AIAgent`](aisdk.AIAgent.md) function, the
software tracks the message history automatically.

Create the initial prompt and convert it to an `aisdk.LLMTextMessage`
object. Create an `LLMMessage` array.

```
messageHistory = aisdk.LLMTextMessage("This is the initial prompt.");
```

Generate a response to the prompt by using the [`generate`](generate.md) function and add the second output argument to the message
history array.

```
[~,message2] = generate(client,messageHistory);
messageHistory = [messageHistory; message2];
```

Ask a follow-up question, add it to the message history, and generate a response by
using the [`generate`](generate.md) function. Add the response to the message history.

```
messageHistory(end+1) = aisdk.LLMTextMessage("This is a follow-up question.");

[~,message4] = generate(client,messageHistory);
messageHistory = [messageHistory; message4];
```
## Input Arguments
<a id="input-arguments"></a>
### `client` — LLM client
<a id="client"></a>

`OpenAIClient` | `OllamaClient`

LLM client, specified as an [`OpenAIClient`](OpenAIClient.md) or [`OllamaClient`](OllamaClient.md) object.

Create a client by using the [`aisdk.LLMClient`](aisdk.LLMClient.md) function.

Data Types: `OpenAIClient` | `OllamaClient`
### `prompt` — LLM prompt
<a id="prompt"></a>

string scalar | character vector

LLM prompt, specified as a string scalar or character vector.

Data Types: `char` | `string`
### `messageHistory` — Message history
<a id="messagehistory"></a>

`LLMMessage` array

Message history, specified as an `LLMMessage` array.

LLM message arrays can contain one or more of these objects:

- [`aisdk.LLMTextMessage`](aisdk.LLMTextMessage.md)

- [`aisdk.LLMImageMessage`](aisdk.LLMImageMessage.md)

- [`aisdk.LLMToolCallMessage`](aisdk.LLMToolCallMessage.md)

- [`aisdk.LLMToolResultMessage`](aisdk.LLMToolResultMessage.md)

The message history can contain:

- The real chat history of an interaction with an LLM

- Example inputs and outputs for few-shot prompting

- Images that models with vision capabilities can use
## Name-Value Arguments
<a id="name-value-arguments"></a>

Specify optional pairs of arguments as
`Name1=Value1,...,NameN=ValueN`, where `Name` is
the argument name and `Value` is the corresponding value.
Name-value arguments must appear after other arguments, but the order of the
pairs does not matter.

Example: `generate(client,prompt,TimeOut=30)` sets the timeout to 30
s.

> [!NOTE]
> For a quick reference on the types of APIs and the name-value arguments they support, see [`Valid Argument Combinations`](#valid-argument-combinations).
### `MaxNumTokens` — Maximum number of generated tokens
<a id="maxnumtokens"></a>


`inf`
(default) | positive integer

Maximum number of generated tokens, specified as `inf` or as a positive integer.

Data Types: `single` | `double` | `int8` | `int16` | `int32` | `int64` | `uint8` | `uint16` | `uint32` | `uint64`
### `ReasoningEffort` — Amount of internal reasoning
<a id="reasoningeffort"></a>

`"auto"` (default) | string scalar | character array

Amount of internal reasoning, specified as a string scalar or character
array.

If `ReasoningEffort` is set to `"auto"`, then
the software chooses the default value of the model used to generate text. The
supported values and the default value depend on the model.

This option is supported only for the OpenAI APIs.

Data Types: `char` | `string`
### `StopSequences` — Stop sequences
<a id="stopsequences"></a>


`[]`
(default) | string array | character vector | cell array of character vectors

Stop sequences, specified as `[]` or as a string array, character
vector, or cell array of character vectors.

When the generated output contains one of the specified stop sequences, the model
stops token generation.

Example:
`["The end.","And that is all she wrote."]`

Data Types: `string` | `char` | `cell`
### `StreamFcn` — Custom streaming function
<a id="streamfcn"></a>

function handle

Custom streaming function, specified as a function handle.

Specify a custom streaming function to process the generated output as it is
generated, rather than having to wait for the end of the generation. For example, you
can use this function to print the output as it is generated.

Example: `@(token) fprintf("%s",token)` prints each token when it
is generated.

Data Types: `function_handle`
### `TimeOut` — Connection timeout in seconds
<a id="timeout"></a>

`120` (default) | nonnegative numeric scalar

Connection timeout in seconds, specified as a nonnegative numeric scalar.

If the model does not respond in the timeout, then the function returns an
error.

Data Types: `single` | `double` | `int8` | `int16` | `int32` | `int64` | `uint8` | `uint16` | `uint32` | `uint64` | `char` | `string`
### `ResponseFormat` — Response format
<a id="responseformat"></a>

`"text"` (default) | 
`"json"` | string scalar | structure

Response format, specified as a string scalar or structure array.

Use the `ResponseFormat` name-value argument to specify the
output format of the generated text. You can request unformatted output, JSON mode, or
structured output. To find out which of these output formats your model supports, see
the model documentation.

If the response format is set to `"text"`, then the generated
output is an unformatted string.

If the response format is set to `"json"`, then the generated
output is a formatted string containing JSON encoded data. To configure the format of
the generated JSON file, describe the format using natural language and provide it to
the model either in the system prompt or as a user message.

To make sure that the model output adheres to the required format, use structured
output. To do this, set `ResponseFormat` to:

- A string scalar containing a valid JSON schema.

- A structure containing an example that adheres to the required format, for
example: `ResponseFormat=struct(Name="Rudolph",NoseColor=[255 0
0])` results in outputs with two fields,`"Name"`
with a string value, and `NoseColor` with a three-integer array
value.

Data Types: `char` | `string`
### `NumCompletions` — Number of generated outputs
<a id="numcompletions"></a>

`"auto"` (default) | positive integer

Number of generated outputs, specified as `"auto"` or as a
positive integer.

This option is supported only for the OpenAI APIs.

Data Types: `single` | `double` | `int8` | `int16` | `int32` | `int64` | `uint8` | `uint16` | `uint32` | `uint64` | `char` | `string`
### `Seed` — Random seed
<a id="seed"></a>

`[]` (default) | integer

Random seed, specified as `[]` or as an integer.

Specify a random seed to enable deterministic model outputs.

For some models, this option has no effect. To learn whether a given model
supports deterministic outputs, see the model documentation.

Data Types: `single` | `double` | `int8` | `int16` | `int32` | `int64` | `uint8` | `uint16` | `uint32` | `uint64` | `char` | `string`
### `Verbosity` — Verbosity of generated output
<a id="verbosity"></a>

`"auto"` (default) | string scalar | character array

Verbosity of generated output, specified as a string scalar or character
array.

If [`ReasoningEffort`](#reasoningeffort) is set to `"auto"`, then
the software chooses the default value of the model.

This option is supported only for the OpenAI APIs.

Data Types: `char` | `string`
### `PresencePenalty` — Presence penalty
<a id="presencepenalty"></a>

`"auto"` (default) | numeric scalar between `-2` and `2`

Presence penalty value for using a token that has already been used at least once
in the generated output, specified as `"auto"` or as a numeric scalar
between `-2` and `2`.

Higher, positive presence penalty reduces the repetition of tokens. Lower,
negative values increase the repetition of tokens.

The presence penalty is independent of the number of times a token appears in the
output, so long as it is repeated at least once. To increase the penalty for every
additional time the model generates a token, use the
[`FrequencyPenalty`](#frequencypenalty) name-value argument.

If the model supports `PresencePenalty` and
`PresencePenalty` is `"auto"`, then the software
uses the default presence penalty of the model.

This option is supported only for the OpenAI APIs.

Data Types: `single` | `double` | `int8` | `int16` | `int32` | `int64` | `uint8` | `uint16` | `uint32` | `uint64` | `char` | `string`
### `FrequencyPenalty` — Frequency penalty
<a id="frequencypenalty"></a>

`"auto"` (default) | numeric scalar between `-2` and `2`

Frequency penalty value for repeatedly using the same token in the generated
output, specified as `"auto"` or as a numeric scalar between
`-2` and `2`.

Higher, positive frequency penalty reduces the repetition of tokens. Lower,
negative values increase the repetition of tokens.

The frequency penalty increases with every instance of a token in the generated
output. To use a constant penalty for a repeated token, independent of the number of
instances that token is generated, use the [`PresencePenalty`](#presencepenalty)
name-value argument.

If the model supports `FrequencyPenalty` and
`FrequencyPenalty` is `"auto"`, then the
software uses the default frequency penalty of the model.

This option is supported only for the OpenAI APIs.

Data Types: `single` | `double` | `int8` | `int16` | `int32` | `int64` | `uint8` | `uint16` | `uint32` | `uint64` | `char` | `string`
### `Temperature` — Temperature
<a id="temperature"></a>

`"auto"` (default) | numeric scalar between `0` and `2`

Temperature value for controlling the randomness of the output, specified as `"auto"` or as a numeric scalar between `0` and `2`. Higher temperature increases the diversity of the output.

If the model supports `Temperature` and `Temperature` is `"auto"`, then the software uses the default temperature of the model.

Data Types: `single` | `double` | `int8` | `int16` | `int32` | `int64` | `uint8` | `uint16` | `uint32` | `uint64` | `char` | `string`
### `TopP` — Top probability mass
<a id="topp"></a>

`"auto"` (default) | numeric scalar between `0` and `1`

Top probability mass for controlling the diversity of the output, specified as
`"auto"` or as a numeric scalar between `0` and
`1`. Higher top probability mass increases the diversity of the
output.

If the model supports `TopP` and `TopP` is
`"auto"`, then the software uses the default top probability mass
of the model.

Data Types: `single` | `double` | `int8` | `int16` | `int32` | `int64` | `uint8` | `uint16` | `uint32` | `uint64` | `char` | `string`
### `MinP` — Minimum probability ratio for Ollama&#x2122; models
<a id="minp"></a>

`"auto"` (default) | numeric scalar between `0` and `1`

Minimum probability ratio for Ollama models, specified as `"auto"` or as a numeric scalar
between `0` and `1`.

Tune the frequency of improbable tokens in generated output using min-p sampling.
Higher minimum probability ratio corresponds to lower diversity.

If the model supports `MinP` and `MinP` is
`"auto"`, then the software uses the default minimum probability
ratio of the model.

This option is supported only for the Ollama API.

Data Types: `single` | `double` | `int8` | `int16` | `int32` | `int64` | `uint8` | `uint16` | `uint32` | `uint64` | `char` | `string`
### `TopK` — Top-k sampling parameter for Ollama models
<a id="topk"></a>

`"auto"` (default) | positive numeric scalar

Top-k sampling parameter for Ollama models, specified as `"auto"` or as a positive numeric
scalar.

Sample only from the `TopK` most likely next tokens for each
token during generation. Higher values of `TopK` correspond to
higher diversity.

If the model supports `TopK` and `TopK` is
`"auto"`, then the software uses the default top-k sampling
parameter of the model.

This option is supported only for the Ollama API.

Data Types: `single` | `double` | `int8` | `int16` | `int32` | `int64` | `uint8` | `uint16` | `uint32` | `uint64` | `char` | `string`
### `TailFreeSamplingZ` — Tail free sampling parameter for Ollama models
<a id="tailfreesamplingz"></a>

`"auto"` (default) | numeric scalar

Tail free sampling parameter for Ollama models, specified as `"auto"` or as a numeric
scalar.

Tune the frequency of improbable tokens in generated output. Higher values of
`TailFreeSamplingZ` correspond to lower diversity. If
`TailFreeSamplingZ` is set to `1`, then the
model does not use this sampling technique.

If the model supports `TailFreeSamplingZ` and
`TailFreeSamplingZ` is `"auto"`, then the
software uses the default top-k sampling parameter of the model.

This option is supported only for the Ollama API.

Data Types: `single` | `double` | `int8` | `int16` | `int32` | `int64` | `uint8` | `uint16` | `uint32` | `uint64` | `char` | `string`
## Output Arguments
<a id="output-arguments"></a>
### `text` — Output text
<a id="text"></a>

string scalar

Output text, returned as a string scalar.

If the model generates text, then `text` contains the generated
text.

If the model generates only a tool call, then `text` is
`""`.
### `message` — Output LLM messages
<a id="message"></a>

`aisdk.LLMTextMessage` | `aisdk.LLMImageMessage` | `aisdk.LLMToolCallMessage` | LLM message array

Output LLM messages, returned as an `aisdk.LLMTextMessage`,
`aisdk.LLMImageMessage`, `aisdk.LLMToolCallMessage` object, or an
LLM message array containing one or more of these objects.

The data type of the output LLM message depends on the LLM. For example, if the
model generates text, then the output is an `aisdk.LLMTextMessage` object. If
the model generates text and a tool call, then the output is an LLM message array
containing an `aisdk.LLMTextMessage` and a `aisdk.LLMToolCallMessage`
object.
### `info` — Information about output generation
<a id="info"></a>

structure

Information about output generation, returned as a structure with these fields:

- `Tokens` — Information about token usage, returned as a
structure with these fields:

  - `NumInputTokens` — Number of input tokens, returned as
a nonnegative integer.
  - `NumOutputTokens` — Number of output tokens, returned
as a nonnegative integer.
  - `NumTotalTokens` — Total number of tokens, returned as
a nonnegative integer.
  - `NumCachedInputTokens` — Number of cached input tokens,
returned as a nonnegative integer.
